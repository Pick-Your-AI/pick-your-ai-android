# Android help and public reports

This is a guest-local Android planning preview. The bundled examples are
synthetic; they do not establish real compatibility, price, capacity or quality.
The phone is the planning client, and the preview does not run your AI stack.
There is no direct in-app support submission or verified private reporting
destination.

## Get help without sending data

Open **Help and report a problem** in the preview for local guidance and the app
version/code and Android API. It is available without a network request. Reading
help does not save, change or share a draft.

Use **Save locally** and wait for the saved acknowledgement. If saving is
uncertain or another saved copy changed, preserve visible edits and review the
status before acting. **Reopen saved copy** can replace pending edits, so read
its confirmation. **Save pending edits as a new local draft** can preserve an
eligible pending form separately. If creation is unconfirmed, inspect the
reported local ID in **Manage local drafts** before creating another copy.
Retained versions keep their exact saved content and pins; inspecting an old
version does not make its evidence current.

The original-fixture diagnostic validates the bundled example separately from
your edited draft. **Review diagnostics** previews a small report of compiled
app metadata, Android API and finite local status values. Drafts, component IDs,
queries, paths, files, logs and credentials are excluded. Choosing to share it
opens the system app chooser with the exact reviewed text. You select the
destination; the preview does not confirm delivery or a response. See the
[existing diagnostic boundary](docs/LOCAL_DIAGNOSTICS.md).

## Choose a public report

**GitHub issues and attachments are public.** Check
[existing Android reports](https://github.com/Pick-Your-AI/pick-your-ai-android/issues)
before submitting. Use one of the focused forms:

| Route | Use it for | Safe information to provide |
| --- | --- | --- |
| [Android app bug](https://github.com/Pick-Your-AI/pick-your-ai-android/issues/new?template=android-bug.yml) | Reproducible app behavior, recovery, layout, accessibility or navigation | App version/code, Android API, invented inputs, exact controls, expected/observed behavior and a safe status |
| [Android evidence correction](https://github.com/Pick-Your-AI/pick-your-ai-android/issues/new?template=android-evidence-correction.yml) | A public claim, source, item/version, recorded price, attribution or evidence presentation | A public reference, affected public pin/value, proposed correction, conditions and any missing support |

The app shows the complete fixed destination before **Open GitHub**. It sends no
draft text, diagnostic report, attachment or prefilled issue content. GitHub may
require sign-in. Opening a page does not submit a report: review the text there
and use GitHub's explicit submit action yourself. The GitHub form accepts your
own text and attachments; the app cannot inspect or redact those later inputs.

If a browser cannot be opened, the app retains the destination and shows a fixed
failure. Local help remains available. Close and review the destination again
before another attempt; there is no automatic retry or fallback upload.

Use a fresh synthetic draft and invented values for reproduction. Do not send
private drafts, customer data, personal information, credentials, raw files or
logs. If a screenshot is useful, inspect and remove private content before
posting it. The optional diagnostic field may be left empty; copying a report
there is your separate manual action after reviewing the complete report.

## Triage and response limits

CompleteDotTech accepts maintainer triage of these two categories for the current
implementation session, including its controlled synthetic intake checks. This
records in-session responsibility; it does not establish ongoing support hours,
a future duty rota, a private inbox or a response-time guarantee.

The maintainer's visible issue response should record the category, safe
reproduction result, relevant public version/source, disposition and next step.
Submitting a form alone is not evidence of that response. A useful triage result
is one of the following:

| Finding | Handling and review |
| --- | --- |
| Reproducible Android defect | Keep the report in this project, link the existing implementation issue/PR, reproduce with safe inputs and record the reviewed fix and verification |
| Android evidence presentation or adapter defect | Retain the affected public pin and conditions; fix the Android boundary without inventing new upstream evidence |
| Shared evidence, price, contract or rights change | Record the requested correction and link the existing canonical authority below; obtain its review before promoting or rewriting shared outputs |
| Duplicate | Link the existing report and preserve any additional safe reproduction; do not create a competing workstream |
| Unsupported or unverified behavior | Explain the current scope or missing evidence and a concrete recovery/input need; do not report a feature, receipt or fix as delivered |
| Confidential information or sensitive security details | Do not quote, request or copy the material into a public follow-up; apply the private-information handling below |

Shared authorities remain research
[#41 for evidence and freshness](https://github.com/Pick-Your-AI/pick-your-ai-research/issues/41),
[#39 for pricing](https://github.com/Pick-Your-AI/pick-your-ai-research/issues/39),
[#40 for contracts](https://github.com/Pick-Your-AI/pick-your-ai-research/issues/40)
and [#60 for source-use rights](https://github.com/Pick-Your-AI/pick-your-ai-research/issues/60).
These are coordination links, not automatic cross-repository submissions or an
alternate catalog publisher. Preserve pinned historical facts and distinguish a
proposed correction, reviewed evidence and published client data. A synthetic
fixture is never vendor evidence.

Before a report is closed as fixed, link the accepted code or evidence change,
state the exact verification performed and retain any remaining gap. Build and
simulated UI checks do not prove installed browser behavior, a support receipt,
physical-device results or operational readiness. A safe controlled intake check
must receive its own attributable receipt and category disposition before it is
described as successfully triaged.

## Local deletion and external copies

**Manage local drafts** offers explicit review and confirmation before deleting
a selected draft and its retained revisions. Interrupted cleanup requires
**Retry local cleanup**. Follow the displayed status; do not treat an uncertain
cleanup as completed. This removes local files and does not claim secure erasure.
Other drafts and copies previously sent through another app are outside that
deletion's scope.

For a report you posted to GitHub, use that platform's editing/removal controls
and help process. A public follow-up about removal should identify only the
affected issue and safe scope, without repeating the content. Removing visible
text does not guarantee removal from edit history, notifications, caches or
copies held elsewhere. Deleting a local draft cannot delete a GitHub issue or a
recipient's copy.

## Security and private information

**Private reporting is unavailable in this preview: no private destination has
been verified.** Do not use these public forms for confidential material,
credentials or sensitive security details. This statement describes the verified
route available here; it does not claim that every GitHub security feature is
globally disabled. No security email address, monitored inbox or private advisory
submission is advertised.

If a credential was exposed, revoke or rotate it with its issuer. Remove the
visible public material where you can and use the hosting platform's help for
further removal; do not repost it to ask for help. A maintainer handling such a
report should avoid quoting it, identify the affected public location without
repeating secrets, and record only a safe disposition. A confidential intake or
incident response requiring a private channel remains unavailable until an
actual destination and receiving responsibility are verified.
