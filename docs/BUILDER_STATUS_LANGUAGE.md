## Decision: name the subject before its state

Every status must say what it describes: an input, a storage operation, a candidate, one rule, a report, an evidence claim, a cost record or a comparison. Preserve the selected identity and scope alongside it. A single reassuring badge cannot represent all of those subjects.

For example, a draft can contain unanswered inputs, a retained rule can have outcome `fail` with severity `warning`, and an inspected cost record can declare `partial` coverage. These facts can coexist. Present each fact and its own explanation; do not let the warning erase the pricing gap or let the subtotal decide compatibility.

The existing guest notice `R.string.unknown` says that compatibility, capacity, quality and price are unknown because no analysis or quote has run for that draft. It is a scope notice, not a `CompatibleOptionVerdict.UNKNOWN`, a counted rule finding, or a returned cost estimate. The current summary's `draft_summary_evaluation_unavailable` and `draft_summary_cost_unavailable` identify the missing current-result consumers more precisely. Preserve both meanings when integrating a future receiver; text matching must never construct domain state.

### Unknown, skipped, absent and unsupported

Use the actual reason alongside these words. In the explicit CD1 policy, unresolved compatibility applicability yields `unknown`; unresolved recommendation applicability can yield `skipped`. A known false applicability or `not_applicable` can also yield `skipped`. Therefore the generic label **Skipped** must not universally expand to “proved inapplicable.” Preserve `Cd1Finding.position`, `answerState` and `reason` when that particular caller exists. These CD1 rules do not change the frozen diagnostic profile or install a new Activity consumer.

The candidate helper ranks `pass` and `skipped` together only when comparing whether an affected finding worsened. That internal rank does not convert a skipped finding into a pass or override the report's separate counts.

`PreviewCatalogValueState` distinguishes `MISSING`, `EXPLICIT_UNKNOWN`, `EMPTY_COLLECTION`, `CONTAINS_UNKNOWN` and `SUPPLIED`. The corresponding detail resources expose absence and incomplete lists without turning omissions into unsupported capabilities. The frozen schema identifies catalog-reference fields separately: the literal ID `unknown` in such a field remains a supplied identifier; it is not a global sentinel. Other source text remains literal according to its admitted field, rather than acquiring meaning through a display-string comparison.

An unsupported schema/profile, reader limit or unavailable exact pin describes this reader's ability to produce a result. It does not establish that a provider lacks a capability. Conversely, a typed failed assertion remains a failure even if some unrelated evidence is unknown. This document neither changes assertion evaluation nor authorizes lowering unresolved evidence into a known Boolean.

## Explanation and action contract

An explanation should expose the information the reader needs to decide the next action, in this order:

1. **Subject and scope.** Identify the current form, exact saved revision, candidate slot, synthetic fixture or explicitly selected retained snapshot. Preserve Build identity and the available source/profile pins. A missing binding is an explicit limitation, never a guessed latest version.
2. **Independent labels.** Show input completeness, candidate verdict, rule outcome/severity, report result, grade, cost coverage and currentness only where each has its own source. An absent axis stays unavailable; do not derive it from another label.
3. **Condition and affected selections.** Preserve rule ID, code, admitted message and affected IDs. Use role/version context only from the existing same-report checked context. Retained-snapshot affected kinds are not a proven minimal cause. Missing or ambiguous selection context remains explicit.
4. **Assumptions and evidence.** Keep recorded observations, expectations, source versions, assumptions, meter/period/currency and missing classifications under their respective admission/disclosure limits. A producer's `measured` method or confidence label is still a declaration until its evidence is qualified. A record with no evidence is not thereby correct or complete.
5. **Specific next step.** Link only to the existing authorized destination: the required-input editor, explicit pin recovery, selected finding/context, recorded conditions, or a fresh attempt under current authority. If qualified evidence or a real consumer is absent, say what input/consumer is needed. Do not fabricate an evidence-upload action, compatible alternative, quote, background fetch or deployed remedy.

All recorded text keeps its literal and privacy boundary. The fixed findings context deliberately withholds settings, notes, extensions, owner and credential references; this template does not authorize disclosing them. Source links retain the current host-policy and explicit external-app confirmation. Opening a source is neither checking nor verifying its claim. Full recorded values retained in memory/storage are not automatically public export material.

Failures must keep their real recovery semantics. A retry can mean reloading the same pin or creating a fresh inspection ticket; it cannot adopt a newer storage baseline or undo an uncertain write. Existing dialog generations, Activity lifetime checks, record identity and CAS checks remain prerequisites for every action. This document adds no callback, automatic remediation or save behavior.

## Accessibility and wording review

Use visible text for the subject, state and severity; color or an icon may supplement them. Retain whole quantity resources for total catalog/source/rate counts, including later pages. Preserve explicit zero versus unavailable, missing versus empty, and displayed versus retained counts. A truncation notice must not imply that omitted evidence was reviewed or that a displayed subset is complete.

Existing live regions and guarded actions provide a source basis for review, not proof of spoken order or announcements. Review proposed copy in its actual heading, details, error/retry and before/after context. Keep the source label and independent severity understandable at expanded text and in RTL layout; do not let source controls or a bare number replace the application label. Installed TalkBack, focus order, announcement timing, keyboard and physical-layout outcomes require their own observations. No such execution was performed for this document.

An Android UX/accessibility reviewer should assess S01–S28 against the vocabulary and surface tables, record any remaining wording or consumer mismatch by source identity, and retain the distinction between UI-source observations, Core contracts and Combined proposals. No named human's review, customer comprehension result or operating commitment is implied by authoring this draft.
