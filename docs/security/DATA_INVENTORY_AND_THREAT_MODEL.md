## Security objectives and boundaries

Protect private planning information, object ownership and share authority; preserve catalog/evidence provenance; reject untrusted input without corrupting acknowledged work; disclose every intentional external transfer. A compromised/rooted device or a recipient's copied export cannot be made trustworthy by app controls. Local storage isolation is not a promise of protection from an unlocked device's user, OS compromise or screenshots.

| Boundary | Crossing and authority | Required invariant |
| --- | --- | --- |
| B1 User / Android UI | Workload text, selections, keyboard, clipboard, accessibility services | Treat all input as potentially sensitive; no background clipboard reads; no automatic transfer from an input field. OS input services are outside app control. |
| B2 App memory / durable private storage | Drafts, revisions, pins, migrations, caches and outbox | Transactional writes, explicit save acknowledgement and identity partitioning; no silent reset on corruption. |
| B3 App / OS and other apps | Intents, document providers, exported components, share sheet, backup, screenshots, notifications | Least privilege; explicit export preview and temporary URI grants; untrusted inbound content; backup rules verified on supported devices. |
| B4 App / distribution and data authority | Bundled assets, remote manifests, catalog, prices, evidence | Authenticate the source independently of integrity hashes; bind each result to exact accepted versions and rights. |
| B5 App / shared service | Authenticated or guest capability requests, drafts, evaluation and sync | TLS and server-enforced authority for each object/action; client IDs, ownership fields and link verification are not authorization. |
| B6 Service / persistence and operators | Database, object storage, queues, caches, audit logs, backups | Least-privilege service access, redaction, retention and deletion propagation; no public storage default. |
| B7 App or service / third parties | Browser, identity provider, diagnostic destination, payment/store or notification provider | Explicit purpose, minimum payload, independently reviewed processor/retention arrangements before enablement. |
| B8 Build system / installed app | Dependencies, build jobs, signing material and update channel | Reviewed dependency provenance and protected signing; no secrets in app assets or public build logs. |

## Builder-to-share walkthrough

1. **Discover:** F03 enters through B4, remains synthetic in preview, and pins catalog/price/evidence versions. An untrusted evidence URL is display data, not permission to fetch it. Real-data promotion requires T06 checks and exact accepted publication/rights inputs.
2. **Build, evaluate and compare:** F01/F02 cross B1/B2. Preview computation stays on device with no inference or provisioning. Any future evaluation request is F08 crossing B5 and must get a payload/retention review. Backgrounding, process death and late results exercise T09.
3. **Save:** acknowledge only durable local state. No remote-save or backup guarantee is implied. F09 is a separate potential off-device transfer and must be tested even when there is no INTERNET permission.
4. **Import/export:** when enabled, incoming F04 crosses B3 and cannot overwrite the active plan. Outgoing F05 must pass the safe projection and user preview before B3/B7; the recipient may retain a copy. The current preview exposes neither transfer. No automatic share merely from viewing a record.
5. **Share:** public links are absent from the implemented preview. When accepted, F06 passes B5/B6/B7 via the canonical service and T04; guest use still needs server authority. F07/F08 apply if sync/account scope is selected. Read-only viewing neither imports nor grants owner access.
6. **Delete/recover:** remove the chosen draft and history, staging files, matching local derived data and queued work; explicitly distinguish clearing public cache, revoking a link and deleting an account. Server copies, backups, recipient exports and diagnostic retention have separate paths/limits. Failed deletion must report pending/failure rather than completed erasure.

Keyboard/accessibility services and OS screenshots are B1/B3 exposures even without app networking. Future notification previews must not display private workload details by default. Operators and third-party processors are recipients, not implicit trusted extensions of the user.
