# Android 03.05 — Module Registry (modules.toml) proposal

<!-- android-triage:20261030:start -->

## Goal
Establish the module registry (`modules.toml`) for the android preview repository so any
contributor can find the right slice of code and its boundaries without opening the whole
tree. This records the module boundaries already selected by the reviewed Android #34
native-architecture decision; it does not create a new architecture or change any contract.

## Scope and decision basis
- Mirrors the reviewed and merged **Android #34** decision
  ([native architecture](../../../proposals/02-native-architecture.md)) and the
  [repository scope record](../../../REPOSITORY_SCOPE.md).
- Two top-level Gradle module trees: `:core` (SDK-independent Kotlin) and `:preview`
  (opt-in synthetic Android diagnostic, `-PandroidPreview=true`).
- `:core` sub-modules registered where there is real cohesion; single-file packages stay as
  unregistered single-file leaf packages, which may still expose public declarations.
- `:app` and `:data` are registered as **future** modules (not created yet).
- The frozen `contracts/v1` value adapters and the `contracts` module are **read-only
  except through the versioned review path** (research Pick-Your-AI/pick-your-ai-research#40).

## Proposed registry (summary)
- **`:core`** — SDK-independent Kotlin core (contract adapters, domain state, analysis,
  evidence semantics, JVM filesystem/cache adapters).
  - `contracts` — **FROZEN**. Frozen v1 contract value adapters + strict validator.
  - `evidence` — answer-state normalization (answered / unknown / not-applicable /
    not-selected), membership, placement. Sub-modules: `answers`, `membership`, `placement`.
  - `evaluation` — compatibility recomputation and reference/retained-snapshot evaluation.
  - `drafts` — draft selections and snapshot projection.
  - `pricing` — pricing / cost-estimate value handling.
  - `comparison` — two-build / two-evaluation comparison.
  - `importing` — bounded JSON reader and local snapshot revision (the import boundary).
  - `preview` — core-side preview-logic helpers (distinct from the `:preview` UI module).
  - Leaves (unregistered): `analysis`, `cache`, `configuration`, `invalidation`,
    `navigation`, `resources`.
- **`:preview`** — synthetic Android diagnostic UI (native Views, lifecycle), depends on
  `:core`, opt-in.
- **`:app`**, **`:data`** — future, registered as planned.

## Coverage check
All 14 immediate packages below `ai.pickyour.core` are accounted for: eight
registered packages and six single-file leaves in `[leaf_packages.core]`, outside
`module.*`. Nested evidence packages are included recursively under `evidence`.
Containment (`submodules`) is separate from dependency edges (`depends_on`).

## Dependency snapshot and limitations

The package dependencies are regenerated from Kotlin imports at source head
`554770d92bac0cb499a0f2ee36b86f4b7c717639`. For each registered core package, collect
`import ai.pickyour.core.<name>` recursively, deduplicate and sort the first package
segment, and exclude self-imports. Leaf names are valid dependency targets.
This is an observed import graph, not an exhaustive symbol-level dependency analysis
or a declaration that the existing coupling is the desired architecture.

Two existing cycles are explicitly retained: `contracts` ↔ `evidence` and
`comparison` ↔ `pricing`. In particular, frozen contract adapters import evidence
status values and importing utilities; they are not dependency-free. Recording
these cycles authorizes no refactor or frozen-v1 change. Top-level dependencies
remain Gradle module dependencies; future entries describe plans only.

## Constraints (hard)
- **Frozen contracts are read-only** except through the versioned review path (research
  #40). No one patches frozen v1 to make a test pass.
- The string `'unknown'` must never be interpreted as a known fact (Android #27); evidence
  grade, candidate verdict, rule outcome, and severity remain independent.
- This registry records boundaries; it makes no framework, module-placement, or release
  decision. Shared contract/schema authorities (research #40, #41) stay canonical.

## Deliverable
[`modules.toml`](../../../../modules.toml) at the repository root, validated for
syntax, with each module carrying
`path`, `owns`, `does_not_own`, `depends_on`, `invariants`, and (where relevant)
`frozen` / `gotchas` for active entries. Future entries are minimal planned records.
Named source references use existing `.kt` filenames relative to the entry path,
not assumed type names. Module cards and generated public API indexes do not exist;
`card` and `public` keys are omitted rather than pointing to nonexistent files.

## Acceptance criteria
- [ ] `modules.toml` parses cleanly and records every `ai.pickyour.core.*` package.
- [ ] The `:core`/`:preview` boundary matches the reviewed #34 decision.
- [ ] The `contracts` module is marked frozen and its read-only-except-versioned-review
      rule is stated.
- [ ] `:app` and `:data` are registered as future (not created).
- [ ] The `core.preview` / `:preview` naming collision is documented.

## Local validation of the correction

- TOML parsing, exact 14-package inventory (8 registered + 6 leaves), recursively
  collected cross-package imports, active directory paths, named source files and
  containment folders were checked against the pinned source above.
- Relative Markdown links and `git diff --check` were checked for these two files.
- No build, tests, emulator/device, store or production validation was run or claimed
  for this documentation-only correction. CI does not validate this registry.
- Existing acceptance checkboxes remain pending receiving review; this supporting
  registry does not deliver or close Android #27 or assign its implementation owner.

## Receiving review roles
Central contract owners (research #40/#41) and affected Android consumers.
