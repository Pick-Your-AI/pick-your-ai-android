### Explicit projection and retained-only acknowledgment

A candidate requires enabled `primary` workload, deployment_mode, model and
context_policy selections. The immutable aggregate rejects duplicate selection
IDs and every duplicate `(kind, role)` pair, including disabled entries, enforces
active cardinality-one constraints, and rejects missing link endpoints/duplicate
link IDs. Catalog ID/version/kind triples must resolve even for disabled
selections. Versionless references with multiple target versions are withheld
without choosing first/latest. Active models require explicit `provided_by`
links to their declared active providers; no graph edge is turned into user wiring.

Catalog/ruleset/graph and optional Pricebook identities, revisions, original byte
hashes and structural validation must agree. Ruleset/graph/rate duplicate IDs and
unresolved Pricebook item/version references are withheld. Graph cycles remain
allowed. Optional T3–T5 unknown intent, contradictory enabled entries under a
disabled tier, or enabled intent with no typed representation are distinct
withheld outcomes; disabled/empty branches create no global optional requirement.
Conflicting typed workload inputs are not silently reconciled. Review-size and
counter bounds are explicit local admission limits, not changes to frozen v1.

Only explicit workload fields enter frozen objectives. The free-text objective,
context and primaryModel, every opaque optional activation/selection/settings
group, local format/revision/legacy reference, metadata and represented history
are retained in the separate source member. Every logical path, including null or
empty values and escaped metadata keys, belongs to the acknowledgment inventory.
No free text is hidden in invented schema extensions. Caller-supplied owner
references are recorded values, not authenticated actor or rights evidence.

The acknowledgment is bound to the exact review object, chosen descriptors and
durable source revision/hash. Missing/extra paths or another review's token fail.
Later edits, optional changes, metadata changes or restore invalidate it even if
visible values return to an earlier state. Pending/unsaved form text is outside
this durable-source API. A future creation UI must disclose that boundary and
collect the real explicit choice; the API does not claim that a human already did.

### Version and retention matrix

| Version boundary | Supported operation and preserved input |
| --- | --- |
| Local format 1 | Read preserves exact original bytes and records a legacy anchor without inventing absent earlier entries. An explicit successful save/restore migrates to format 4, retaining entered content/metadata and the original source hash/artifact in the live source store. |
| Local formats 2–3 | Read and unchanged save preserve bytes. An actual edit/restore migrates to format 4, retaining all old entries, numbering, restore links, metadata and any legacy anchor. New workload/typed aggregates are unanswered/empty in memory, never inferred from free text. |
| Local format 4 | Typed selections/settings and their action disclosures retain their established meaning. Reads, no-ops and rejected role edits do not upgrade the envelope. |
| Local format 5 | An actual role edit appends one format-5 revision. Later saves/restores retain format 5; old format-4 CONFIGURE actions remain settings-only, and role changes cannot rewrite unrelated fields. |
| Projection profile 1 and frozen Build 1.0.0 | Exact retained-source plus explicitly supplied typed facts yields a distinct Build with lifecycle `draft`. Frozen schemas/fixtures/generators are unchanged. An unsupported future profile/schema is withheld without choosing a substitute. |
| Private bundle/index version 1 | Framing, member roles, lengths/hashes, mathematical identity, source history and all manifest-to-artifact relationships are rechecked on reopen. Unknown/corrupt versions remain inspectable as retained storage and cannot become a guessed Build or new current head. |

The retained bundle guarantees the exact **current source envelope and its
represented typed history**, not every predecessor serialization. A
`legacy_source_hash` remains an unchanged historical provenance reference whose
raw target is not a bundle member and need not remain retrievable after source
deletion. The predecessor-absent legacy test checks this precise subset.
Original-format restoration or migration replay needing those older bytes must
obtain them separately or report unavailable; this record grants neither.

Build identity is `(Build ID, mathematical revision)`: `1`, `1.0` and `1e0`
are one revision identity even though their raw spellings remain distinct.
Identical complete-bundle retry is idempotent; a different complete bundle at the
same identity conflicts, including an already retained unreferenced bundle.
Complete source/artifact bytes, not merely a decoded equality check, determine
that conflict.

One complete bundle is forced before index activation under library → source →
archive/cache locking. Both source review authority and archive-head CAS must
remain current. Missing/corrupt seals or index metadata do not authorize a new
generation-0 archive; an old captured index is read-only historical authority,
never a replacement current CAS. Failed activation/completion returns a distinct
not-published or uncertain result requiring reopen. Earlier entries and complete
orphans remain intact. Bounds refuse new data rather than evict saved snapshots.

Managed publication requires a canonical archive directory disjoint from the
entire library namespace, so deleting another draft cannot remove its snapshots.
Standalone callers retain the source-disjoint rule and their provisioning
responsibility. Source edit, restore or deletion does not cascade into the
independently retained archive. There is no automatic expiry or removal API/UI in
this model; eventual product integration must disclose retention and supply its
explicit removal choice. This private format is not an export or sharing format.
