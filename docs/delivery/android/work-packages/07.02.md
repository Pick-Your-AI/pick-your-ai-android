## Selected behavior and authority

The real Add form and exact-selection replacement form capture an immutable
request containing the original local stored record and store identity, local
revision/hash, catalog and rules bytes/pins, kind, role, replacement selection,
settings and form epoch. The worker receives that captured object, a fresh attempt
ticket and bounded candidate page. A complete result is accepted only for that
same request and still-current UI/storage authority. Edits, role/settings ABA,
catalog changes, a newer durable store head, pause and destruction retire old
results and actions. Recalculation clears old rows into an unresolved state.

For each candidate, the baseline is the exact same draft with only the requested
slot empty. Replacing a primary never promotes a retained secondary; replacing a
secondary preserves the primary, selection identity, settings and incident links.
The existing frozen finding operation evaluates both hypothetical inputs. Only
worsened findings for affected rules count toward the candidate: pass/skipped
rank 0, unknown rank 1 and fail rank 2. A new failure yields INCOMPATIBLE; otherwise
a new unknown yields UNKNOWN; otherwise the relative verdict is COMPATIBLE.
The candidate verdict is separate from every per-rule outcome. Inherited unknowns
or failures remain visible and can coexist with a compatible relative choice.

The initial filter exposes compatible entries. Explicit controls expose unknown
and incompatible entries, their separate page counts and actual rule/reason
details; counts describe the current ten-row page. Inspecting a choice grants no
write authority. A one-use explicit confirmation returns to the existing
canonical command and compare-and-swap path; storage can still reject a newer
revision. No evaluation automatically changes or saves a draft.

This private profile admits existing typed local selections/workload for a blank
or incomplete stored draft. It does not manufacture a shared Build, ID, revision,
owner, lock, timestamp or policy. Free-text local draft fields are not interpreted
as frozen policy. Unknown optional activation, existing enabled components in a
disabled tier, or a proposed enabled candidate in that disabled tier withhold the
batch. Explicitly enabled empty optional slots remain fillable. Comparison never
activates a tier. Frozen Build/archive admission, including `minItems`, remains
unchanged; no private local finding becomes an archived or reusable shared report.
