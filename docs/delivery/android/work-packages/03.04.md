## Concrete implementation and result boundary

The [normalized placement guide](../../../NORMALIZED_PLACEMENT_PROFILE.md)
describes the nine production Kotlin files and their explicit API. `PlacementBasis`
binds the full original Build, exact selected catalog name/version associations,
operation, named inputs and normalization/source-policy identity. Its immutable
bytes and framed key prevent a changed valid basis from reusing a qualification.

`PlacementAnswers` preserves each original CD1-0.2 state, detached value, requested
path, actual source path, provided assumption and preset source. Qualification
binds that original input/hash, profile, field/fact, pointer and actual domain.
All supplied declared original references and hashes are preflighted, including
unused records. Malformed/dangling declared originals reject; a valid old basis
or wrong established route/engine/replica/physical scope remains ineligible and
unknown for the requested dependent predicate.

One CD-6 graph supplies the exact engine, host, device and base roles. Required
wrong-kind/disabled known targets retain their own consistency failure; absent
exact versions stay unknown. Complete support-condition inventories prevent a
caller from dropping a known condition while retaining a claimed complete list.
Unknown support evidence does not erase an otherwise established deployment mode.

Memory accounts for unique qualified physical allocations per owning pool and
scenario. Equal amounts, hashes or consumer names do not prove sharing. Device
instances, address-space/partition/tenancy, runtime/replica/rank/admission/stage,
copies, nonnegative charge completeness and scenario/transition coverage remain
explicit. `conservative_all_resident` and `qualified_scenarios` are supplied
assumptions; the consumer does not switch between them silently. A qualified
disjoint failing subset can remain fail beside other unknown nonnegative charges.
Uncertain alias, residency or source eligibility cannot qualify that witness.

CD-2 ByteCount operands are canonical decimal **strings** parsed directly to
BigInteger. CD11 context counts are exact original JSON **integer tokens**, also
using BigInteger. Boolean, floating, exponent or string aliases cannot pass the
other profile's count admission. Positive context input/shared limits and the
explicit zero-permitted output/policy operands retain their distinct rules.

The context package preserves CD11-0.1 on the original CD1-0.1 reader. Shared
semantics compares input plus reserved output to the vendor window. Separate
semantics compares input and output independently and admits no provided shared
vendor cap. An optional total policy is a separate predicate. Required N/A stays
unknown; only designated optional-cap N/A removes that constraint. Upper-bound
failure with no definite lower failure yields `mayNotFit`; another independently
qualified definite failure is retained without an uncertainty-only label.

Results retain their actual observations, checked-only prerequisites, scoped
causes and conditional-capacity label. A capacity/context pass is not overall
compatibility, operational support, rights approval, hardware fit or deployment
readiness. The Android device is not inferred to be the described target runtime.

### Defensive cycle carrier limitation

The accepted central note explicitly selects cyclic adapter lineage as
unresolved. Its normalized
[migration prototype](https://github.com/Pick-Your-AI/pick-your-ai-research/blob/449a29be1752a3c545709da466c7d53fc18fef73/tests/t0_migration_prototype.py),
blob `b9fa277038cf00e9e22d6b16c556864f8ba83033`, permits model or fine-tuned-model
nodes in that synthetic traversal; the exact
[test_adapter_cycle_is_unknown reference](https://github.com/Pick-Your-AI/pick-your-ai-research/blob/449a29be1752a3c545709da466c7d53fc18fef73/tests/test_t0_migration.py),
blob `2b21f98da409cbb68e4d13a22c11d857a7da352d`, uses two adapters.

The new B3 fixture therefore uses two distinct synthetic selected adapters,
distinct catalog IDs, exact versions and explicitly qualified role/operation/
artifact facts. The retained carrier passes structural admission, but the frozen
`base_model_ref` description still names catalog kind `model`. This deliberately
defensive cycle is **not a semantically valid frozen-v1 model-base configuration**,
not support evidence and not a revision of that field. The result proves bounded
UNKNOWN/BINDING_CYCLE behavior and retained originals at the chosen normalized
layer. No schema, production enum, parser or base-kind policy is changed to admit it.
