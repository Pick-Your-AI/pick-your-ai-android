## Currentness, negative cases and recovery

DraftCurrentInputs copies original Catalog, DependencyGraph and Ruleset bytes
before admission. Requests bind private store, local revision/content hash/format,
all three artifact hashes and exact catalog/graph/rules identities. The store path
participates privately in the digest and is not displayed or logged. The before
basis is the previous acknowledged source, even if superseded or withheld.

The same canonical durable head is read before evaluation and again before
admitting its complete result. Both reads must match the capture. Opaque attempts
reject foreign output and A→B→A revival. The Activity separately checks saved
form, selected draft, storage/lifecycle authority and exact input/catalog objects.
These are boundary checks, not continuous external-file monitoring or atomic
disk/UI-frame locking.

Tests cover caller-byte mutation; malformed, oversized, duplicate and unsupported
input; same revision/hash in different stores; removed old graph edges; input
gaps; durable mutation during evaluation; pre/post read failure; foreign output;
edit/revert; reentrant old completion; retry; real save conflict and canonical
reopen; pause/recreation; and unchanged history. An empty affected-ID list is
only that observation, never compatibility or readiness.

The 13 current-check Activity methods also cover existing picker, History,
catalog and revision authority. Nine sibling methods add actual snapshot,
resource, fixed-Findings, Help, Diagnostics and Privacy entry, callback replay,
late inventory, fresh-child controls and unchanged analysis/binding/durable bytes.
Window-only retirement preserves accepted inline historical records; lifecycle
retirement remains separate. Automatic storage/catalog refresh retains its
narrower boundary and captured Help identity.

PreviewDraftReads is a test-only correction: only exact BUSY permits one finite
owned-worker marker wait and one further canonical read. It advances no UI clock,
retries no write and hides no second failure. Held-lock BUSY controls remain
direct; product storage locking and scheduling are unchanged.
