## Outcome and selected boundary

The adopted Kotlin `:core` and platform Views `:preview` client now connects the exact
catalog search/detail result to the existing typed selection transaction. The detail
action captures the acknowledged draft, local revision, storage authority and
catalog identity. The existing chooser and form carry kind, explicit role and
optional replacement identity. The managed transaction validates exact item/version,
cardinality, role and expected revision before one add or replacement.

The new bounded local component route carries only kind, catalog item ID, opaque
version and snapshot digest. Recognized delivery provides navigation identity.
An explicit inspection and a separate explicit Use in draft/chooser/form action
are required before a mutation. Cold entry requires a deliberate local-draft choice.
Warm entry preserves the existing draft, pending builder fields, browse context,
open form and ordinary 750 ms autosave schedule.

This is the local preview handoff selected by the literal issue. The existing
exported launcher treats explicit external Intents as untrusted. No new VIEW
filter, public domain association, backend endpoint or frozen v1 field is added.
Public shared-build App Links retain [#124](https://github.com/Pick-Your-AI/pick-your-ai-android/issues/124).
The client is not selected as an inference runtime by this handoff.

## Original implementation subtasks

- Carry explicit draft ID, expected local revision, kind, role and optional replacement selection through search/detail selection navigation.
- Validate selected item/version and cardinality against the active draft before committing one transactional add or replacement.
- Route stale, missing or unsupported-version selections to a recoverable explanation, preserving the original draft and user navigation context.
- Normalize supported incoming component links through a bounded trusted route parser; require an explicit add action before changing a build.

The first three subtasks are implemented through the existing `SelectionEditSection`
and canonical managed-store command, reached from the new detail origin. Incoming
identity is normalized independently and never manufactures those draft fields.

## Failure, recovery and timing cases

| Condition | Required and observed behavior |
| --- | --- |
| A newer writer changes the acknowledged draft or removes the replacement target | Detect it before mutation, preserve the newer record and explain the stale origin. No automatic retry adopts the newer revision. |
| Catalog identity changes or the requested version/snapshot is missing | Retire the original selection action or display the bounded unavailable explanation. Do not substitute a newer available item or activate a retained catalog. |
| Cardinality-one or duplicate-role validation fails | Preserve the current form and entered correction context; only a later explicit valid confirmation can write. |
| Builder fields have unacknowledged input | Disable selection authority while keeping fields and normal autosave timing. Inspection does not save the draft. |
| A component form is already open | Incoming delivery cannot dismiss, submit or replace it. |
| Malformed UTF-8, duplicate/encoded query keys, unknown fields, oversized values, grants, MIME type, ClipData or selector | Reject the input as a whole; never echo the raw URI or derive write authority from it. |
| Corrupted normalized checkpoint | Reapply bounded identity validation; do not reparse the original Intent or automatically select a local draft. |
| Cold entry across recreation | Remain unbound until the user explicitly selects a local draft. |
| Pause, background, destruction or a retired dialog | Retained callbacks cannot open a new window, navigate or mutate the draft. |
| Repeated recognized entry at 749 ms | Preserve the ordinary single autosave at 750 ms. The old detail capture remains retired; a new explicit capture is required after acknowledgement. |

The accepted `AutosaveUiClock` supplies test-only frame delivery without advancing
a Handler millisecond deadline. Production debounce remains exactly 750 ms.
The incoming suite includes actual JVM native-graphics measurement at 320 dp,
RTL and font scale 2, then follows the real explicit action. This is simulated
Android evidence, not an installed emulator or physical-device observation.
