## Selected local interface and exact inputs

`LocalSnapshotEvaluator.prepare(snapshot, resource, cost, profile)` accepts a
`RetainedDraftSnapshot` obtained from the existing private archive decoder. That
opaque type already passed the complete retained source, mathematical identity,
member hash/length, selection/role/cardinality/link/reference and exact artifact
admission described in [the archive](LOCAL_SNAPSHOT_ARCHIVE.md) and
[projection](DRAFT_SNAPSHOT_PROJECTION.md) records. The adapter does not fabricate
a Build from partial or free-text editor fields and does not issue source authority.

The wrapper then independently bounds and validates the exact raw Build, Catalog,
Ruleset, DependencyGraph and optional Pricebook. It checks the immutable artifact
descriptors and all Build locks. The graph's full schema and identity are required;
the three-input frozen evaluator does not consume graph edges. This explicitly
selected strategy reevaluates the complete Ruleset, with no graph pruning or
invented graph-derived verdict. It is not a second typed graph parser.

The archive's semantic checks retain exact catalog item ID/version/kind, all
selection and link identities, the four primary foundation roles, optional intent,
provider linkage and the existing eighteen catalog reference mappings. A catalog
containing multiple versions of one ID cannot become a last-entry-wins evaluator
lookup: the local profile explicitly withholds an ambiguous Catalog. No pin uses
"latest" and missing evidence is never replaced with another version.

| Slot | Required behavior |
| --- | --- |
| Build | Exact retained raw bytes; full mathematical ID/revision; schema and local bounds. |
| Catalog | Exact ID/revision/hash/length plus the Build catalog lock and unambiguous ID lookup. |
| Ruleset | Exact ID/version/hash/length, full schema and Build rules locks. |
| DependencyGraph | Exact ID/mathematical revision/hash/length, full schema and Build graph locks; bound but no edge pruning. |
| Pricebook | Exact optional ID/revision/hash/length and matching Build lock. Absence is distinct from a missing locked artifact. Its presence supplies no CostEstimate. |
| ResourceEstimate / CostEstimate | `NotSupplied` is allowed. Every `Requested` slot is withheld, even if its declared confidence or coverage sounds sufficient. |

Requested estimates are independently checked for availability, raw digest, strict
JSON, schema/version, declared ID and exact Build ID/mathematical revision before
being withheld. Those checks do not establish units, selected applicability,
estimator/calibration provenance, cost line arithmetic, Pricebook rate eligibility,
complete coverage or source-use permission. No producer-supplied label can enable
an external metric in this profile. A requested missing input remains
`REQUESTED_UNAVAILABLE`, not `NotSupplied`; malformed, foreign, hash-mismatched,
unsupported-version and locally unsupported inputs retain their actual diagnostics.
An unavailable slot does not erase independently checked bindings for another slot.

## Evaluation and report admission

`SnapshotEvaluator.evaluate(request)` is a synchronous stable local interface.
`LocalSnapshotEvaluator` performs the fixed Kotlin computation itself, with no
caller report, executable metadata, metric override or backend endpoint. The
complete computed report is re-admitted through `ReferenceReportAdapter` against
the exact captured Build and Ruleset; its original serialized bytes must match.
The wrapper also checks the complete report identity, full Build revision, fixed
reference time, per-rule code/message/remediation and empty finding-evidence arrays.

The existing receiver checks schema, rule count/order/IDs/severity, affected active
selection IDs, all report lock fields, outcomes, counters, result and readiness.
Those consistency checks alone would not prove arbitrary predicate execution.
Provenance here is the actual wrapper-owned local computation, followed by these
complete result checks. Returned public descriptors are immutable and contain no
raw retained source or DraftVersion. Foreign computed results cannot acquire the
active request's opaque authority merely by having consistent report fields.

The output retains the reference's literal `2026-10-16T09:00:00Z` fixture time.
A distinct `observedAt` records the actual local observation; clock failure returns
an explicit failure. Neither field establishes evidence freshness. Interruption
before or after computation returns cancellation, and work-limit/unsupported/
invalid-input/binding/output/engine failures do not return partial reports.

### Supported semantic and numeric subset

- Every rule is retained in Ruleset order. False applicability is `skipped`;
  unknown applicability is `unknown`. `all(false, unknown)` is false and
  `any(true, unknown)` is true; missing measurements do not imply that every rule
  must be unknown. `exists`, null, optional activation and boolean domination
  retain their original meanings.
- Outcome and severity are independent. An error/fail makes the report invalid;
  otherwise an unknown makes it indeterminate; otherwise it is valid in this
  profile. A warning/fail can coexist with valid. Readiness is blocked or
  needs_review according to the frozen policies, never a universal Ready pass.
- Affected selection IDs are sorted active selections of affected kinds, not a
  proven minimal causal set. Remediation is displayed, never executed.
- Decimal strings use exact decimal comparison and the existing maximum twelve
  fractional digits. Recursive bool/integer equality and supported container,
  set, string and pointer behavior remain the accepted bounded Python subset.
  Raw floating/exponent operands, including nested values and those opposite
  missing operands, are explicitly unsupported when reached. Non-string substring
  operands, nested unhashable set operands and non-ASCII array-index spellings
  remain unsupported. No successful integer or decimal is narrowed to `Long`.
- The evaluator requires integer tokens for Build revisions and their graph lock
  revisions. Thus a schema-valid raw Build revision `1e0` is explicitly unsupported
  here even though archive identity correctly treats it as mathematical revision 1.
  Raw artifact counters are separately admitted and bound mathematically; graph
  bytes are not evaluated as operands. These are local limits, not frozen-schema
  errors or silently repaired input spellings.
- Context sums use supported integer inputs. VRAM accounting uses the existing
  exact twenty-eight-digit Decimal arithmetic subset; selected-device sums do not
  prove pooled usable memory, topology, calibrated fit or sustainable capacity.
- Each evaluated input is bounded at 256 KiB, 20,000 tokens and 4,096 UTF-16 string
  units, with the strict reader's depth, key, number, UTF-8, duplicate-key, surrogate
  and single-object limits. Work defaults to 250,000 operations (maximum 1,000,000),
  with the existing traversal and string-scan accounting. This is not a wall-clock
  timeout or proof that all parsing/allocation work is charged to that counter.
- Resource and monthly-cost operands receive no external evidence in this profile.
  No nominal weight size, VRAM total, retained Pricebook, absent cost, declared
  confidence or completeness flag invents a measured metric, zero cost or budget pass.

The twenty-six existing diagnostic goldens cover the declared supported cases;
they do not certify every schema-valid DSL expression. Two separate report-adapter
fixtures use development metric overrides to test report/decimal representation;
those overrides are not inputs supported by this actual consumer.

## Read-only Android authority and lifecycle

`PreviewSnapshotAnalysis` owns a captured archive index/entry plus a fresh opaque
attempt. The actual `AnalysisIdentity` includes the complete request digest in
its `draftId` field. Its `Long` revision value 0 is explicitly a local immutable
view epoch, not a conversion of the Build revision. The full mathematical Build
identity and every exact input participate in real coordinator equality. The
coordinator ticket, session attempt and returned exact request object must all
match before a result becomes current. Retry, repeated selection, ABA transitions,
cancel, replacement and close cannot revive an earlier authority token.

All archive IO and evaluation run on the worker. UI completions are dispatched to
the owning Activity and read the current state, never a stale captured rendering.
The native `Inspect saved snapshots` entry lists real retained entries and requires
an explicit selection. It displays the exact mathematical identity, captured
index/bundle/pins, observation and fixture times, all four outcome counts,
independent severity, findings and explicit failure/unknown limits. Dialog callback
guards require the same showing window and session. Pause and destruction retire
the request before old windows or queued results can act. Recreation starts with
no accepted result and requires a fresh explicit inspection.

The native archive directory is `filesDir/retained-snapshots`, outside the complete
managed `noBackupFilesDir` library root. The inspector requires an existing normal
directory, both existing cache directories and the namespace seal before opening.
`LocalSnapshotArchive.loadExisting()` never initializes a namespace, creates an
empty active index or repairs missing metadata. Ordinary filesystem locking and
verification remain required; this is logical read-only inspection, not a claim
that no lock file can be opened. Missing, empty and corrupt layouts are distinct.
The app does not create demo snapshots or silently provision an archive. The
existing explicit archive API supplies retained inputs; creation/removal UI is
separate product integration, with the existing disclosure and retention limits.

The source draft may have been legitimately deleted after independent archival.
The viewer reads the complete retained bundle, without requiring that source to
remain live. A captured older index can support a historical read even if the
current index later disappears; it never repairs the head or supplies current
archive CAS. The view has no draft persistence adapter, no save/restore/select
action, no network or sharing action, and no pending-form input. It does not alter
the current editor, active-draft pointer, source history or archive entries.
