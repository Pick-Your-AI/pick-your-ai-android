# Typed evaluation-suite settings

This is the bounded `evaluation_suite` CONFIGURE contribution to Android [#99](https://github.com/Pick-Your-AI/pick-your-ai-android/issues/99) and the existing [#41](https://github.com/Pick-Your-AI/pick-your-ai-android/issues/41) planning surface. It uses the three fields in the frozen Selection schema. It does not change frozen contracts, generic ADD, legacy raw recovery, the shared T6 guidance, another editor, or the accepted command and storage authority.

## Values and admission

| Frozen setting | Native input | Preserved meaning |
| --- | --- | --- |
| `minimum_score` | Explicit Supply control and exact JSON number text | Omitted is distinct from supplied zero. Negative, fractional and values above 100 are admitted when structurally valid. The frozen contract provides no range, percentage scale, unit or recommended threshold. |
| `dataset_size` | Explicit Supply control and exact JSON integer text | Omitted is distinct from invalid empty input; a supplied value must be an integer at least 1. Wide integers and admitted integral decimal/exponent nodes are not narrowed. |
| `gate_required` | Not supplied / False / True choice | All three states remain distinct from the outer Selection enabled flag. A requested gate does not enforce one. |

The adapter reads frozen metadata and parses each numeric field independently with the existing bounded exact JSON reader. It does not trim, localize, round, coerce the literal `unknown`, accept a trailing document, or admit injected sibling keys. Untouched admitted numeric nodes retain their representation. All removals and replacements are applied before the existing complete-Selection form validator checks the final payload, including retained notes/extensions and shared size limits. A field failure produces no partial command; diagnostics identify a field and fixed problem category without echoing input.

There is no evaluation execution, measured score, verified dataset count, model/runtime comparison or quality/safety claim. Existing core T6 guidance and unavailable-evidence explanations remain visible in the form.

## Saved records and private recovery

The editor captures the existing draft, saved revision, Selection and catalog identities. It uses the established owned worker, complete-Selection preparation and managed compare-and-swap save. Invalid edits, cancellation, no-op commits and stale/deleted authority retain their existing outcomes. The input controls, tri-state picker and commit action retire with the form, Activity pause, changed authority or an in-flight save; a retained callback cannot recreate write authority.

The private tag is `typed-evaluation-suite/1`. Its exact closed 12-key Bundle carries five original identities, two nullable raw numeric strings, a supplied/value pair for the nullable Boolean, and the saving flag, plus version and kind. The two strings share the existing 20,000 UTF-16-unit limit. Overflow retains no prefix. Android automatic view-state and autofill are disabled for these inputs, and the IME no-personalized-learning flag remains a request.

Recovery requires explicit review. Invalid numeric text remains pending input for correction; it is not a schema value or an acknowledged save. Changed draft/revision/Selection/catalog identities and a captured in-flight save allow only read-only inspection. No checkpoint replays a command or replaces captured identities with current ones. The legacy raw version-1/version-2 readers and the other typed recovery tags retain their own dispatch.

## Verification scope

The new Core cases exercise optional presence, exact numerical and Boolean values, malformed/locale/injected text, whole-Selection limits, retained payload, managed storage/no-op/stale/deleted behavior and explicit frozen projection. Activity cases exercise real simulated form, worker and storage flows, captured identities, invalid correction, cancel/no-op, retained callbacks, pause/recreation, changed durable authority and in-flight acknowledgment. Parcel cases exercise exact primitive shape, bounds, identity preservation and sibling-reader separation. A narrow RTL/large-text case checks native control size, complete visible text, guidance and scroll reachability.

Two additive workflow guards require the exact declared Core, Activity and checkpoint case identities, matching totals, no repeats and no failed, errored or skipped cases. Source declarations and this guide do not claim successful execution. Each natural configured run has its own source/preparation identity and original evidence; prior editors' results do not qualify this contribution.

The whole #99/#41 criteria, governed answer-state representations from #27/#83, canonical receiving records, installed evaluation-suite journeys, physical accessibility, real evaluation services and release acceptance remain separate.
