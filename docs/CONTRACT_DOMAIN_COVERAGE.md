# Contract and domain coverage inventory

This is the version 1 engineering inventory for [Android #32](https://github.com/Pick-Your-AI/pick-your-ai-android/issues/32). It maps the fixed accepted Android source `a24792eeea1e20977ddb3dd8942d7ce300bc7856` to existing executable cases and explicit remaining work. It does **not** complete #32 or replace the canonical website receiving record at `docs/delivery/android/work-packages/15.01.md`.

The [machine-readable inventory](contract-domain-coverage-v1.json) enumerates all **14 frozen schemas**, the separate registry's **29 kinds**, and a first set of **32 domain invariant groups**. Schema and kind membership are complete for this source. Property-by-property and kind-by-operation coverage are still partial. The case references identify source methods or factories, not a newly executed test total.

## Read the evidence correctly

| State | Meaning | What remains separate |
| --- | --- | --- |
| Source reference | The exact source blob and named executable method/factory were checked; its assertions support the stated outcome. | Actual execution, expanded dynamic attendance and exhaustive coverage. |
| Attributed execution record | A named public original-output receipt records results for its own checkout, event, run and scope. | Reusing its total as proof that a different checkout or every inventory row passed. |
| Reviewed limitation | A precise invariant and limitation have an actual criterion-specific receiving decision. | General documentation of a restriction, or a generic review flag. This inventory grants none. |
| Pending gap | A missing map, original execution join or receiving decision is explicit. | Treating an empty case list, an example or a successful job badge as accepted coverage. |

All source entries are pinned to the historical basis. References must be rechecked when an owning implementation changes; unrelated main changes do not require inventing a new execution for unchanged source. The JSON's `recorded_executions` section retains the actual checkout of each receipt. Its `reviewed_limitations` list is empty because this engineering contribution makes no new criterion-specific limitation decision.

## Update discipline

For a scoped update, identify the accepted source, retain the original source/receipt identities, read the exact named assertions, and update only affected rows. A dynamic factory is one source reference; enumerate its actual generated case identities before claiming attendance. A limitation needs a precise receiving record. Validate JSON, unique IDs, frozen membership, referenced paths/methods, hashes and links as part of review.

No new permanent guard is introduced by this initial historical inventory. The existing frozen integrity and conformance qualifiers retain their ordinary roles. If later use turns a current test symbol or fixture identity into an enforced acceptance claim, propose a focused consistency check for that demonstrated risk with negative controls and separate review; do not make a documentation inventory a replacement runtime oracle.
