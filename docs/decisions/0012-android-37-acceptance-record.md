## Decision and alternatives

Place **only Android #37 / 03.04** in `Pick-Your-AI/pick-your-ai-android`, retaining
the same relative path. The record is the single criterion, implementation,
failure/recovery, prerequisite-intake and receiving record for the selected
synthetic normalized Android placement profile. The
[original mapping](../PLACEMENT_RELATIONSHIPS.md) remains an immutable historical
input apart from its explicit current-record pointer.

Keeping the new record in the website would separate this native consumer and
its original source/test evidence from their accepted code location. Publishing
duplicate records would create competing acceptance histories. The narrow local
placement keeps the implementation and accountable observations together while
preserving the original intended website location as history.

This decision does not relocate the shared contract queue, an evaluator service,
source-use authority or shared saved-build semantics. Research #40 remains the
central version/compatibility authority; research #41/#42 and canonical website
service/consumer authorities keep their existing scope. Android #35 remains the
shared-service placement gate. No new wire format, endpoint, frozen-v1 field,
default dispatch, website deployment or Apple record is selected here.

No prerequisite edge, parent, assignee, estimate, Project field, release rule or
other record location changes. Android #21 is consumed only for the exact
frozen/source/API-storage boundary stated in 03.04; its broader incomplete
criteria are not inferred complete. The existing Apple #35 unsupported-v1
acceptance and 98 neutral placement cases remain distinct from this executable
normalized consumer.
